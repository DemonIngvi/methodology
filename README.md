# methodology — правила и инструменты ведения документации LLM-агентами

Общий, независимый от проекта набор правил, сценариев, шаблонов и контрактов инструментов, по которым LLM-агент (и человек) ведёт проектную документацию: архитектуру, спеки, интеграции и данные, Deploy, задачи, R&D, решения, ревью и подтверждения ролями.

> Собрано из «Справки» проекта agent-architecture на 2026-10-13; обновляется только вручную по запросу. Автоматической синхронизации с исходным проектом нет.

## Для кого

- **Любой LLM-агент:** Claude Code, Codex, Cursor, Gemini, Copilot и другие. Всё написано обычным Markdown; точка входа — [AGENTS.md](AGENTS.md), её читают большинство агентов. Для Claude Code — [CLAUDE.md](CLAUDE.md) (ссылка на `AGENTS.md`).
- **Человек**, который хочет, чтобы агент менял документацию предсказуемо: по одному документу, по методологии его типа, с проверкой и без выдуманных фактов.

## Главные идеи

1. **Правило в момент правки, а не чтение всех правил.** Правил много; агент получает выжимку для конкретного файла (команда `route`), а не читает всю папку `rules/`.
2. **Один документ за раз, по цепочке.** Место в иерархии → методология типа → правка → проверка → следующий документ по графу связности.
3. **Массовые изменения — партиями**, а не по одному документу.
4. **Один факт — один источник.** Остальные места — ссылки или генерация.
5. **Не выдумывать.** Нет факта — открытый вопрос, а не догадка.
6. **Расхождение нашёл — запиши причину и правило** в журнал отклонений; исправление без правила не закончено.
7. **Подтверждение ролями** — отдельным проходом, экономно, честно: 🤖 агент, 👤 человек.

## Как подключить к проекту

1. Скопируйте в корень репозитория `AGENTS.md` (и `CLAUDE.md`, если используете Claude Code) и папку `rules/`. При желании — `skills/`, `agents/`, `templates/`.
2. **Адаптируйте таблицы** — они и есть настройка под проект:
   - [rules/structure.md](rules/structure.md) — уровни, вкладки компонента, общие разделы, где лежат файлы;
   - [rules/doc-types.md](rules/doc-types.md) — строка на тип документа: колонка «Где» — шаблоны путей вашего репозитория;
   - [rules/doc-graph.md](rules/doc-graph.md) — связи между документами;
   - [rules/change-process.md](rules/change-process.md#single-source) — таблица «факт → источник»;
   - [rules/approvals.md](rules/approvals.md) — какие роли подтверждают какие документы.
3. Замените в `AGENTS.md` команды-заглушки (`doc route`, `doc next`, `doc check`…) на свои; что они должны делать — [tools/README.md](tools/README.md). Начать можно без инструментов: агент выполняет те же шаги вручную по таблицам.
4. Подключите проверку ссылок: `python tools/mdlinks.py .` — битые относительные ссылки, якоря и «сироты» в Markdown (зависимостей нет).
5. Удалите методологии, которые проекту не нужны (например, `deploy.md` для библиотеки), и строки о них в `rules/README.md` и `rules/doc-types.md`.

## Обозначения

| Знак | Значение |
|---|---|
| `D-N` | решение (ADR) с номером |
| `R-<спека>-NN` | требование с постоянным ID |
| `I-N` / `S-N` | интерфейс между компонентами / хранилище данных |
| `Z-<код>-N` | замечание проверки ролями |
| `О-N` | строка журнала отклонений |
| ✅ / ⏳ / ❌ / 📌 / ❓ | готово / ждёт / отказ / решение владельца / открытый вопрос |
| 🤖 / 👤 | проверено агентом в роли / человеком |
