# methodology — правила и инструменты ведения документации LLM-агентами

Общий, независимый от проекта набор правил, сценариев, шаблонов и контрактов инструментов, по которым LLM-агент (и человек) ведёт проектную документацию: архитектуру, спеки, интеграции и данные, Deploy, задачи, R&D, решения, ревью и подтверждения ролями.

> Собрано из «Справки» проекта agent-architecture на 2026-10-13 (методология R&D — v3.3 [второй слой «техническое решение»: дерево качества, сценарии, ATAM-lite / CBAM-lite, fitness-функции, ADR]; данные — YAML по единице со строгой схемой, механика до ролей в lint, пакетная проверка ролями с защитой от шаблона, учёт расхода токенов — от 2026-10-13; обновление 2026-10-14: слой 2 R&D, проверенный факт и `review-batch --pages`, колонка «Тип» параметров, защита ID при записи данных, покрытие сценариев подзадачами — правилом, процессы замера finding-fix / arch-change / rules-change, агент doc-tool-editor, источник до коммита 21258f4); обновляется только вручную по запросу. Автоматической синхронизации с исходным проектом нет.

## Для кого

- **Любой LLM-агент:** Claude Code, Codex, Cursor, Gemini, Copilot и другие. Всё написано обычным Markdown; точка входа — [AGENTS.md](AGENTS.md), её читают большинство агентов; по типу задачи она сразу отправляет к одному сценарию ([таблица](AGENTS.md#task-entry)). Для Claude Code — [CLAUDE.md](CLAUDE.md) (ссылка на `AGENTS.md`).
- **Человек**, который хочет, чтобы агент менял документацию предсказуемо: по одному документу, по методологии его типа, с проверкой и без выдуманных фактов.

## Главные идеи

1. **Правило в момент правки, а не чтение всех правил.** Правил много; агент получает выжимку для конкретного файла (команда `route`), а не читает всю папку `rules/`.
2. **Один документ за раз, по цепочке.** Место в иерархии → методология типа → правка → проверка → следующий документ по графу связности.
3. **Массовые изменения — партиями**, а не по одному документу.
4. **Один факт — один источник.** Остальные места — ссылки или генерация.
5. **Не выдумывать.** Нет факта — открытый вопрос, а не догадка.
6. **Расхождение нашёл — запиши причину и правило** в журнал отклонений; исправление без правила не закончено.
7. **Подтверждение ролями** — отдельным проходом, экономно (пачка компонента за все роли, механику ловит lint), честно: 🤖 агент, 👤 человек.
8. **Скрипт, а не LLM; минимум токенов.** Всё повторяемое — команда, проверка или сценарий. Агент работает с компактными машиночитаемыми данными (YAML по единице, карточки), полные документы перегенерируются один раз в конце; расход замеряется ([журнал](rules/token-costs.md)).

## Как подключить к проекту

1. Скопируйте в корень репозитория `AGENTS.md` (и `CLAUDE.md`, если используете Claude Code), папки `rules/` и `tools/`. При желании — `skills/`, `agents/`, `templates/`.
2. **Адаптируйте таблицы** — они и есть настройка под проект:
   - [rules/structure.md](rules/structure.md) — уровни, вкладки компонента, общие разделы, где лежат файлы;
   - [rules/doc-types.md](rules/doc-types.md) — строка на тип документа: колонка «Где» — шаблоны путей вашего репозитория;
   - [rules/doc-graph.md](rules/doc-graph.md) — связи между документами;
   - [rules/change-process.md](rules/change-process.md#single-source) — таблица «факт → источник»;
   - [rules/approvals.md](rules/approvals.md) — какие роли подтверждают какие документы.
3. Создайте конфиг инструмента: `python tools/doc init` → `doc.config.toml` (раскладка путей, роли, граф связей, форматы ID; [установка и конфиг](tools/README.md#install)); затем `python tools/doc check` и хуки агента ([хуки](tools/README.md#hooks)). Пример настроенного проекта — [examples/minimal](examples/minimal/README.md). Запуск: `tools/doc …` (Git Bash, Linux, macOS — файл сам находит Python 3.10+), `tools\doc.cmd …` (cmd.exe), `python tools/doc …` (любая ОС). Начать можно и без инструмента: агент выполняет те же шаги вручную по таблицам.
4. Минимальная проверка без конфига: `python tools/mdlinks.py .` — битые относительные ссылки, якоря и «сироты» в Markdown (зависимостей нет).
5. Удалите методологии, которые проекту не нужны (например, `deploy.md` для библиотеки), и строки о них в `rules/README.md` и `rules/doc-types.md`.

## Обозначения

| Знак | Значение |
|---|---|
| `D-N` | решение (ADR) с номером |
| `R-<спека>-NN` | требование с постоянным ID |
| `I-N` / `S-N` | интерфейс между компонентами / хранилище данных |
| `Z-<код>-N` | замечание проверки ролями |
| `О-N` | строка журнала отклонений |
| ✅ / ⏳ / ❌ / 📌 / ❓ | готово / ждёт / отказ / решение владельца / открытый вопрос |
| 🤖 / 👤 | проверено агентом в роли / человеком |
