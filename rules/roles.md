# Роли документации

← [Правила](README.md) · [подтверждения](approvals.md) · [проверяющий по роли](../agents/doc-reviewer.md)

Роли — кто пишет, проверяет и утверждает документы. Агент может выполнять любую роль, но **проверяющий — всегда отдельный проход**, не тот же, что писал. Персоны продукта (пользователь, администратор…) — отдельно: их отыгрывают при исследовании историй ([User Stories](user-stories.md)).

## Участники

| Роль | Отвечает на вопрос | Выход готов, когда |
|---|---|---|
| **Владелец продукта** | что важно, сколько стоит, что выбрать? | вопросы 📌 закрыты, приоритеты утверждены |
| **Постановщик** | зачем и что меняем? | proposal: проблема, границы, затронутые спеки |
| **Аналитик историй** | кто что делает и что может пойти не так? | персоны, истории, процессы с артефактами, конфликты отыграны |
| **Автор R&D** | почему именно так? | R&D по [методологии](rnd.md) |
| **Автор критериев приёмки** | как поймём, что сделано? | спека проходит [критерии полноты](spec-criteria.md), RTM без разрывов |
| **Архитектор** | где живут данные, как связаны модули, как развёрнуто? | параметры и интерфейсы, схемы, вид развёртывания, технологии |
| **DevOps-инженер** | как развернуть, обновить, восстановить, что при отказе? | нагрузка и развёртывание, бэкапы, FMEA |
| **Инженер сборки и поставки** | как собрать, откуда взять и как безопасно запустить? | [Deploy](deploy.md) компонента |
| **Разработчик** | реализуемо ли так, как написано? | параметры, интерфейсы и сценарии проверены на реализуемость |
| **Администратор (настройки)** | понятны ли настройки, разумны ли значения? | настройки, умолчания и границы |
| **Пользователь** | решает ли это мою задачу? | истории подтверждены |
| **Безопасность** | где утечка, лишние права, лицензионный риск? | права, секреты, сетевые политики, лицензии |
| **Тестировщик (QA)** | как проверить каждое требование? | сценарии превращены в тесты, нагрузочный тест спланирован |
| **Проверяющий** (подроли: аналитик, техлид, архитектор) | всё ли верно и связано? | ревью записано, проверки зелёные |
| **Агент-исполнитель** | как реализовать задачу по спеке? | задача выполнена, приёмка пройдена |

## Права на документы

**W** — пишет · **R** — проверяет и предлагает правки · **A** — утверждает.

| Документ | Владелец | Постановщик | Аналитик историй | Автор R&D | Автор критериев | Архитектор | Эксплуатация | Безопасность | QA | Исполнитель |
|---|---|---|---|---|---|---|---|---|---|---|
| proposal | A | W | R | | R | R | | | | |
| User Stories, персоны, процессы | A | R | W | | R | R | | R | R | |
| R&D | A | | R | W | | R | R | R | | |
| Решения | A | | | W | | R | R | R | | |
| Архитектура, данные | | | | R | | W | R | R | | |
| Спека | | R | R | | W | R | R | R | R | |
| Параметры и интерфейсы спеки | | | | | R | W | W | R | R | |
| Трассировка, вопросы | A | R | R | R | W | R | | | R | |
| Задачи, Roadmap | A | W | | | W (приёмка) | R | R | | R | статус |
| Ревью | R | | | | | W | W | W | W | |
| Правила | A | R | R | R | R | W | R | R | R | |
| Код | | | | | | R | R | R | R | W |

- Агент-исполнитель **не меняет** спеки и правила — расхождение спеки и реализации оформляет как открытый вопрос.
- Вопросы 📌 закрывает только владелец продукта.
- Агент в роли отмечается 🤖, человек — 👤.

## Порядок

```
Владелец ─▶ Постановщик ─▶ Аналитик историй ─▶ Автор R&D ─▶ Автор критериев ─▶ Архитектор / Эксплуатация / Безопасность ─▶ QA ─▶ Проверяющий
    ▲                                                                                                                           │
    └──────────────────────────────── 📌 вопросы и замечания ◀────────────────────────────────────────────────────────────────┘
                                                                                     Агент-исполнитель ◀── задачи (после ревью)
```

## Подроли проверяющего

| Подроль | Разрезы вопросов |
|---|---|
| **Аналитик** | полнота поведения (S1–S12), пользователь, данные, трассировка |
| **Техлид** | реализуемость, интерфейсы, отказы (FMEA), тестируемость, пороги и лимиты |
| **Архитектор** | границы модулей, хранилища и владельцы, протоколы, развёртывание, безопасность, единые точки отказа, эволюция |

## Промпты ролей

Промпт роли начинается с чтения правил **своего типа документа** (или выжимки `route`), затем — задача роли, что сделать, чего не делать (не своё — другие роли), что вывести в конце. Готовый промпт проверяющего — [agents/doc-reviewer.md](../agents/doc-reviewer.md).
