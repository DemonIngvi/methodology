# Новое R&D (v3.2)

**Для R&D читай только этот сценарий, шаблон [`templates/rnd.md`](../templates/rnd.md) и нужные якоря [`rules/rnd.md`](../rules/rnd.md) по карте ниже.** `AGENTS.md`, `README.md`, остальные правила и `rules/rnd.md` целиком не нужны.

Как прочитать один раздел (от его якоря до следующего):

```bash
sed -n '/^<a id="e3">/,/^<a id="e4">/p' rules/rnd.md          # этап Э3
awk '/^<a id="/{f=0} /^<a id="greenfield">/{f=1} f' rules/rnd.md   # любой якорь
```

Инструмент `tools/doc` в репозитории методологии пока переносится: команды `rnd <slug> <тема>` и `rnd-check <файл>` будут. Ниже у каждой команды — ручной путь.

## Шаги

1. **Заготовка.**
   - Если `tools/doc` есть — `tools/doc rnd <slug> <тема>` → `rnd/<slug>.md`.
   - Иначе вручную: скопировать [`templates/rnd.md`](../templates/rnd.md) в `rnd/<slug>.md` (папка `rnd/` в корне проекта), заменить `<тема>`.
2. **Реестр.** Строка в реестре R&D: тема (ссылка), вопрос, статус, дата, версия методологии `v3.2`. Где реестр — по [структуре](../rules/structure.md#new-project); в новом проекте без документов — README корня: если его нет, создать по [`templates/project-readme.md`](../templates/project-readme.md).
3. **Новый продукт?** Если продукта, историй и решений ещё нет — сначала прочитать `#greenfield`: G1, G3, G10 проходятся по нему (✅, а не ⚠️).
4. **Этапы** — по карте; каждый этап заканчивается строкой «**Вывод этапа.**» и воротами `Gn ✅ …` (⚠️ — только по `#gate-status`, с 📌 и следующим шагом). Поиск Э4 — одной пачкой по списку кандидатов и видов источников (`#search`).

   | Этап | Якорь | Нужные подразделы |
   |---|---|---|
   | Э1 Вопрос | `e1` | `greenfield` — если продукта и документов нет |
   | Э2 Потребности | `e2` | `greenfield` (источники) |
   | Э3 Опорное решение | `e3` | `evidence`; `greenfield` (как решают без нас) |
   | Э4 Альтернативы | `e4` | `search`, `candidate-card` |
   | Э5 Ценность | `e5` | `evidence`, `kano`; агентные технологии — `ag` |
   | Э6 Перенос и критерии | `e6` | `kano`; потоки — `us-rnd`, `personas` |
   | Э7 Отсев и встраивание | `e7` | `integration` |
   | Э8 Спор ролей | `e8` | `debate` |
   | Э9 Выбор | `e9` | `argument` |
   | Э10 Последствия | `e10` | `consequences`, `greenfield` |
   | Первая страница | `layout` | `deck` |
   | Ворота ⚠️ | `gate-status` | — |

5. **Э10 «Последствия»:** каждая строка — документ и статус ✅ / 📌 (со следующим шагом) / —; внести решение (D-номер) и последствия (спеки, файл данных, API, «Как работает», Deploy, задачи, технологии) по `rules/change-process.md`.
6. **Проверка структуры.**
   - Если `tools/doc` есть — `tools/doc rnd-check <файл>`.
   - Иначе вручную (из корня проекта):
     ```bash
     grep -c '^## Э[0-9]*\.' <файл>          # = 10
     grep -c 'Вывод этапа' <файл>           # = 10
     grep -oE 'G[0-9]+ (✅|⚠️)' <файл>       # G1…G10, у каждой
     grep -E 'G[0-9]+ ⚠️' <файл>             # в каждой такой строке есть 📌 и следующий шаг
     grep -c '^## Источники' <файл>          # = 1; у строки — ссылка, дата (или одна на раздел), уровень А–Г
     ```
7. **Проверка ссылок:** `python tools/mdlinks.py .` (или `tools/doc check`, если есть).
