# Изменение данных и интеграций

Единственный источник — файл данных документации (интеграции, модели, таблицы, структура API); страницы «Интеграции», «Данные», ER-диаграммы и структура эндпоинтов генерируются. Методология — `rules/data.md`, `rules/api.md`.

| Что меняется | Где править |
|---|---|
| Интерфейс (I-код) | запись интерфейса (стрелка = кто вызывает; отметка «данные в ответе»; общая инфраструктура); строка с I-кодом в параметрах и интерфейсах спек **всех** участников |
| Модель (контракт JSON) | поля (имя, тип, обязательность, описание), источник поля (✅ есть / 📘 внешний протокол / 🧩 наше), «почему так», планируемые доработки с D / R; пример — в каталоге API |
| Таблица БД | колонки, ключи, FK + политика (индексы, срок, очистка, миграции); таблицы существующей системы — импортом её схемы |
| Эндпоинт | строка в `api/<компонент>.md`; структура — спецификация API работающей системы или запись о доработке |

Правило имён — в файле данных (`rules/data.md#naming`). Решения в сносках — только со ссылкой на существующие D или R: проверь поиском по решениям и спекам, не выдумывай параметры.

Проверка: `tools/doc check`; модели и имена — сценарий `doc-dual-read`.
