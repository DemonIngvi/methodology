# Изменение данных и интеграций

Источник — YAML по единице в папке данных (файл 1–3 КБ на единицу; раскладка — `rules/data.md#yaml`, схема видов — `[[data.kinds]]` конфига); страницы «Интеграции», «Данные», схемы, ER-диаграммы и карточки генерируются. Сгенерированное руками не правим. Методология — `rules/data.md`, `rules/api.md`.

| Что меняется | Файл единицы (пример раскладки) |
|---|---|
| Интерфейс (I-код) | запись I-кода в `data/integrations.yaml` (стрелка = кто вызывает; «данные в ответе»; общая инфраструктура); строка с I-кодом в параметрах и интерфейсах спек **всех** участников |
| Модель (контракт JSON) | `data/models/<Имя>.yaml`: поля (имя, тип, обязательность, описание), источник (✅ есть / 📘 внешний протокол / 🧩 наше), «почему так», доработки с D / R; пример — в каталоге API |
| Таблица БД | `data/tables/<имя>.yaml`: колонки, ключи, FK, политика (индексы, срок, очистка, миграции); таблицы существующей системы — импортом её схемы |
| Эндпоинт | строка в `api/<компонент>.md`; структура — спецификация API работающей системы или `data/endpoints/<страница>.yaml` |
| Блок, компонент, история, процесс | `data/blocks/<компонент>/<slug>.yaml`, `data/components/<slug>.yaml`, `data/stories/<компонент>/<ID>.yaml`, `data/processes/<компонент>.yaml` |

Шаги (`rules/change-process.md#yaml-path`):

1. `tools/doc unit <ID>` — карточка единицы (блок `компонент/slug`, история, I-код, модель, таблица, путь) вместо страницы и целого файла данных. Вручную — открыть файл единицы.
2. Правка YAML единицы; новый файл → `tools/doc yaml-fmt <папка>` (внесёт в `_order.yaml`; вручную — дописать имя).
3. `tools/doc yaml-check <файл>` → `tools/doc lint <компонент>`. Вручную — сверить поля со схемой вида в конфиге, ID ссылок — поиском.
4. `tools/doc next <файл>` — что перегенерируется и следующий документ; по одному.
5. В конце пути — один раз: сборка страниц → `tools/doc check` → коммит.

Без PyYAML (`pip install pyyaml`) `yaml-check`, `yaml-fmt`, `unit` завершаются ошибкой «нужен PyYAML» — тогда ручной путь выше.

Правило имён — `rules/data.md#naming`. Решения в сносках — только со ссылкой на существующие D или R: проверь поиском по решениям и спекам, не выдумывай параметры. Модели и имена — сценарий `doc-dual-read`.
