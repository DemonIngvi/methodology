# Правка документа: по одному, по цепочке

Документы меняются **последовательно**: закончил один — перешёл к следующему по графу связности. Не правь пачкой все места сразу. Порядок и стоп-условия — `rules/agent-workflow.md`.

## Цикл для каждого документа

1. **Место в иерархии:** `route <файл>` — тип, вкладка, обязательное, источник, методология. Генерируемый файл (`pre <файл>`) — правь его источник.
2. **Методология этого типа:** открой файл из строки «Методология» и прочитай «Из чего состоит», «Как вести», «Чек-лист».
3. **Методология устарела?** Если она молчит о том, что ты меняешь, или противоречит текущему устройству документации — сначала поправь её. Цепочка методологии: инструменты (проверки, сценарии, хуки), потом документы этого типа (`rules/change-process.md#rules-change`).
4. **Факт живёт в одном месте:** значение, поле, конфиг — найди источник (`rules/change-process.md#single-source`), здесь ставь ссылку.
5. **Правка** этого одного документа. Многострочные замены — инструментом правки или скриптом из файла, а не heredoc с экранированием.
6. **Проверка:** `check`.
7. **Следующий:** `next <файл>` — документы на концах стрелок, у каждого своя методология. Берёшь их **по одному** и повторяешь цикл с шага 1. Если документ по смыслу не меняется — по его стрелкам дальше не идёшь.

## Массовые изменения

Много исправлений сразу (замечания ролей, ревью, смена методологии) — не по одному документу: все проверки → коммит состояния → партии по слою и источнику → связанные документы партией → `check`, сборка, коммит один раз на партию (`rules/change-process.md#bulk`).

## Переименование и новый документ

- Переименовал или перенёс документ — `move <старый> <новый>`: файл и все ссылки сразу, без цепочки.
- Новый документ — дай ему входящую ссылку (строка «←», навигация или индекс типа); проверка ловит «сирот» (`python tools/mdlinks.py .`).

## Когда остановиться и спросить

- нужен выбор продукта, изменение противоречит принятому решению D, удаление или новая вкладка;
- факт неизвестен — не придумывай: код, спецификация API, решения; нет — открытый вопрос в спеке.

## Конец цепочки

Очередь пуста → полная проверка (сборка, валидатор спек) → коммит. Расхождение по пути — строка в `rules/deviations.md`: что → почему → правило и проверка. Отчёт: какие документы изменены, в каком порядке, какие методологии обновлены.

Модели, интеграции, имена — сценарий `doc-dual-read`; данные — `doc-data`; новое исследование — `doc-rnd`.
