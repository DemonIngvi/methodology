# Правка документа: по одному, по цепочке

Документы меняются **последовательно**: закончил один — перешёл к следующему по графу связности. Не правь пачкой все места сразу. Порядок и стоп-условия — `rules/agent-workflow.md`. Команды — `tools/doc` ([doctool](../tools/README.md); на Windows — `python tools/doc …`); без инструмента — ручной путь из таблицы команд в `AGENTS.md`.

## Цикл для каждого документа

1. **Место в иерархии:** `tools/doc route <файл>` — тип, вкладка, обязательное, источник, методология. Генерируемый файл (`tools/doc pre <файл>`) — правь его источник.
2. **Методология этого типа:** открой файл из строки «Методология» и прочитай «Из чего состоит», «Как вести», «Чек-лист».
3. **Методология устарела?** Если она молчит о том, что ты меняешь, или противоречит текущему устройству документации — сначала поправь её. Цепочка методологии: инструменты (проверки, сценарии, хуки), потом документы этого типа (`rules/change-process.md#rules-change`).
4. **Факт живёт в одном месте:** значение, поле, конфиг — найди источник (`rules/change-process.md#single-source`), здесь ставь ссылку. Данные (блоки, компоненты, модели, таблицы, эндпоинты, интерфейсы, истории) — YAML по единице: читать `tools/doc unit <ID>`, править файл единицы, `tools/doc yaml-check <файл>` (сценарий `doc-data`).
5. **Правка** этого одного документа. Многострочные замены — инструментом правки или скриптом из файла, а не heredoc с экранированием.
6. **Проверка:** `tools/doc check` (без инструмента — чек-лист методологии и `python tools/mdlinks.py .`).
7. **Следующий:** `tools/doc next <файл>` — документы на концах стрелок, у каждого своя методология. Берёшь их **по одному** и повторяешь цикл с шага 1. Если документ по смыслу не меняется — по его стрелкам дальше не идёшь.

## Массовые изменения

Много исправлений сразу (замечания ролей, ревью, смена методологии) — не по одному документу: все проверки → коммит состояния → партии по слою и источнику → связанные документы партией → `tools/doc check`, сборка, коммит один раз на партию (`rules/change-process.md#bulk`).

## Переименование и новый документ

- Переименовал или перенёс документ — `tools/doc move <старый> <новый>`: файл и все ссылки сразу, без цепочки.
- Новый документ — дай ему входящую ссылку (строка «←», навигация или индекс типа); проверка ловит «сирот» (`tools/doc check` или `python tools/mdlinks.py .`).

## Когда остановиться и спросить

- нужен выбор продукта, изменение противоречит принятому решению D, удаление или новая вкладка;
- факт неизвестен — не придумывай: код, спецификация API, решения; нет — открытый вопрос в спеке.

## Конец цепочки

Очередь пуста → полная проверка (сборка — **один раз за путь**, не после каждой единицы; валидатор спек) → коммит. Расхождение по пути — строка в `rules/deviations.md`: что → почему → правило и проверка. Отчёт: какие документы изменены, в каком порядке, какие методологии обновлены.

Модели, интеграции, имена — сценарий `doc-dual-read`; данные — `doc-data`; новое исследование — `doc-rnd`.
