# Инструменты: doctool и контракт команд

← [README](../README.md) · [AGENTS.md](../AGENTS.md) · [путь изменения](../rules/agent-workflow.md)

Правила сами по себе дороги: агент тратит контекст на чтение всех методологий и всё равно пропускает нужное. Поэтому правило подаётся **в момент правки** инструментом, а проверки — автоматически. Здесь — **doctool** (`tools/doc`): реализация команд, не зависящая от проекта, — всё проектное задаётся в `doc.config.toml` и плагинах. Ниже — установка, конфиг, команды (это же контракт, если пишете свою реализацию), плагины и хуки. Независимая однофайловая проверка ссылок — [mdlinks.py](#mdlinks).

## Установка <a id="install"></a>

1. Скопируйте в проект папку `tools/` (точка входа `tools/doc`, пакет `tools/doctool/`; `tools/doc.cmd` — для `cmd.exe`) и `rules/`; для `rnd` — ещё `templates/`. Запуск: `tools/doc <команда>` в Git Bash, Linux, macOS (первая строка файла — `#!/usr/bin/env sh`: он сам ищет `python3`, `python`, `py` версии 3.10+ и пропускает заглушку Python из Microsoft Store, которая на Windows завершается кодом 49); `tools\doc.cmd <команда>` в cmd.exe; `python tools/doc <команда>` на любой ОС. Нет подходящего Python — понятное сообщение и код 1.
2. В корне проекта: `python tools/doc init` — создаст `doc.config.toml` по [шаблону](doctool/doc.config.template.toml); `init --json` — то же в `doc.config.json`.
3. Заполните конфиг ([разделы](#config)): типы документов, генерируемые файлы, граф связей, форматы ID, компоненты, плагины. Добавьте `.doctool/` в `.gitignore` (пакеты проверки, схемы).
4. `python tools/doc check` — до нуля замечаний; затем [хуки](#hooks).

Требования: Python 3.10+, только стандартная библиотека; для данных YAML по единице (`yaml-check`, `yaml-fmt`, `unit`, журнал расхода в YAML) — PyYAML ([ниже](#data)). TOML читается `tomllib` (Python 3.11+; на 3.10 — пакет `tomli`, если установлен), иначе — `doc.config.json`. Файлы данных (компоненты, модель данных) — JSON, TOML или YAML (YAML — если установлен PyYAML). Корень проекта — ближайшая вверх папка с `doc.config.*` (или `--root` / `DOC_ROOT`). Windows: вывод UTF-8, запись с LF, пути с кириллицей. Без конфига работают `route`, `next`, `check` по таблицам `rules/`, но в проект ничего не пишется.

Пример настроенного проекта — [examples/minimal](../examples/minimal/README.md); тесты всех команд на нём — `python -m unittest discover -s tests`.

## Принципы

- **Без копий правил.** Выжимки строятся из таблиц `rules/` при каждом вызове: колонки «Обязательные разделы», «Правила», «Синхронизировать», «Методология» [doc-types.md](../rules/doc-types.md) находятся по имени типа; роли, их вопросы и «кто что подтверждает» — из [approvals.md](../rules/approvals.md). Изменили таблицу — изменился ответ инструмента. В конфиге — раскладка проекта и, если нужно, переопределения. Без `[[types]]` типы и пути берутся из колонки «Где» таблицы типов.
- **Быстро.** `check` — секунды, без сборки сайта, чтобы его можно было звать после каждой правки.
- **Для любого агента.** Команды — обычный CLI; хуки конкретного редактора — тонкая обёртка над `pre` / `post`.
- **Инструменты соответствуют правилам** — это тоже проверка (`check` включает её): методологии из таблицы существуют, пути в сценариях и `AGENTS.md` есть, `route` узнаёт основной путь каждого типа, у узлов графа есть файлы, роли типов описаны.

| `[rnd]` | папка, шаблон, реестр и формат строки реестра, `check` | rnd, rnd-check, check |
| `plugins`, `builtin_plugins`, `[plugin.<имя>]` | плагины проекта, встроенные плагины, их настройки | все |

| `init [--json] [--force]` | — | шаблон конфига в текущей папке (или `--root`) | 0 |
| `plugins` | — | загруженные плагины, их правила, каталоги ID и команды | 0 |

Синхронизация реестра подтверждений (в `check`, `approve`, `review-queue`): строки ⏳ для обязательных пар «документ × роль» по типу документа; сброс решения в ⏳ с пометкой «текст изменён после решения «✅» от …», если хеш текста изменился (различия в пробелах не в счёт; `version_ignore` — что ещё не в счёт); удаление строк удалённых документов; сводная таблица с «⏳ было ✅ / ❌». Запись реестра — под файловой блокировкой `<реестр>.lock`: параллельные проверяющие не теряют строк; занятая дольше `lock_timeout` — ошибка, брошенная (старше `stale_lock`) — снимается.

## Плагины <a id="plugins"></a>

Проверки, которые зависят от устройства проекта (модель данных, OpenAPI форка, схема БД), — не в ядре, а в плагинах. Плагин — модуль Python: встроенные лежат в `tools/doctool/plugins/` и включаются `builtin_plugins = ["datamodel"]`, плагины проекта — папки или файлы из `plugins = ["tools/doc_plugins"]` (ключи верхнего уровня — до первой `[таблицы]` конфига).

```python
from doctool.api import lint_rule, check_rule, command, ref_kind, card_kind, util as U

@check_rule("purpose")                             # строгое: yield сообщение → check вернёт 1
def purpose(ctx):
    for f in ctx.spec_files():
        if len(U.plain(U.section(ctx.text(f), "Purpose"))) < 50:
            yield f"{f}: Purpose короче 50 символов"

@lint_rule("agent-estimate")                       # нестрогое: yield (компонент, сообщение)
def estimate(ctx): ...

@command("tasks-table", "сгенерировать TASKS.md")  # новая команда tools/doc tasks-table; вернуть код
def tasks_table(ctx, args): ...

@ref_kind("table")                                 # каталог ID для refs карточек: вернуть (regex, множество ID)
def tables(ctx): ...
```

`@migration("вид")` — правило `yaml-migrate`: `fn(ctx, значение, путь)` → новое значение (например, вынести ID из текста в поле); `@migration_report("вид")` — `fn(ctx, значение, путь)` → список строк «осталось текстом». Позиционный вид → именованные поля делает ядро по `positional` схемы.

`@card_kind("api")` — способ карточки страницы для `review-batch` (`card = "api"` в `[[types]]`): `fn(ctx, страница, текст)` → строки (или `(строки, [ID требований])`).

`ctx` — контекст проекта: `ctx.get("plugin.<имя>.<ключ>")`, `ctx.glob(...)`, `ctx.text(путь)`, `ctx.types()`, `ctx.type_of(путь)`, `ctx.requirements()`, `ctx.tasks()`, `ctx.blocks()`, `ctx.components()`, `ctx.component_of(путь)`, `ctx.ids(вид)`. Примеры: встроенный [datamodel](doctool/plugins/datamodel.py) (таблицы и интерфейсы из файла данных: ссылки карточек, I-коды спек, «таблица названа в задаче компонента») и плагин проекта [house.py](../examples/minimal/tools/doc_plugins/house.py) — в том числе проектная механика до ролей: эндпоинт блока есть в каталоге API (`screen-endpoints`), параметры в values → «Пример конфигурации» в Deploy (`deploy-config-example`).

## Данные YAML по единице <a id="data"></a>

Данные документации (блоки, компоненты, модели, таблицы, эндпоинты, интерфейсы, истории) — один небольшой файл на единицу ([правило](../rules/data.md#yaml), [порядок правки](../rules/change-process.md#yaml-path)). Вид единицы описывается в конфиге:

```toml
[[data.kinds]]
name = "story"                          # имя вида = каталог ID для ссылок (ref = "story", refs карточек блоков)
glob = "data/stories/*/*.yaml"
id_pattern = 'US-[A-Z]+-\d+'            # ID — имя файла ({stem}; или id = "{parent}/{stem}", id_field = "id")
component = "{parent}"                  # компонент единицы (для lint и review-batch)
regen = "истории компонента {parent}"   # что перегенерируется из единицы (next, unit)
fields = [
  { name = "role", type = "str", required = true },
  { name = "reqs", type = "list", items = "str", ref = "requirement", required = true },
  { name = "status", type = "str", choices = ["черновик", "принята"] },
]
```

Типы: `str`, `int`, `float`, `bool`, `date`, `list` (`items` — тип или вложенная схема), `dict` (вложенные `fields`), `any`. `ref` — вид единиц data/ или каталог ID (`requirement`, `task`, `[ids.*]`, `[[data.catalogs]]`, `param`, плагины); список каталогов — значение из любого; `also` — регулярка допустимых значений вне каталога. Поле не из схемы — замечание (`extra = true` — разрешить).

**Строгая структура** ([правило](../rules/data.md#yaml-units)):

- *Именованные строки:* `items = { type = "dict", fields = [...], one_of = ["with", "label"] }` — строка таблицы словарём; в YAML такая строка пишется в одну строку (`flow_rows = false` в `[data]` — отключить).
- *Каталоги и подсказка:* значение не из каталога, из `choices` или имя поля не из схемы — замечание с «может быть: …» (ближайшие по `difflib`). Каталоги объявляются в конфиге:

```toml
[[data.catalogs]]
name = "participant"
about = "блок или участник из interfaces.md"
kinds = ["component"]                                      # ID единиц вида
fields = [{ kind = "block", field = "title" }]              # значения поля единиц вида
files = [{ glob = "specs/*/interfaces.md", pattern = '→ ([^|]+?)\s*\|' }]   # регулярка по файлам (группа 1 или всё совпадение)
values = ["планировщик"]                                    # перечисление
```

- *Тип параметра:* `[data.params]` (`glob` файлов спек, `type_col` (по умолчанию «Тип»), `name_col`, `default_col`, `min_col`, `max_col`, `units`, `durations`) — таблицы параметров; `ref = "param"` проверяет имя среди параметров компонента единицы (компонент — `component` вида или `[components] from_path`), `param_value = "<поле с именем>"` — значение по типу: число с границами и единицей, длительность, перечисление; описанное словами не формализуется. Явная необязательная колонка «Тип» (грамматика — [sdd.md](../rules/sdd.md#params): `число $`, `длительность`, `одно из: a, b`, `список <каталог>`, `ссылка <что>`, `строка 3–5 симв.`, `доля окна %`, составной через ` / `) важнее вывода из «По умолчанию / Мин / Макс».
- *«нет: <почему>»:* `none_ok = true` у спискового поля разрешает строку `нет: <причина>` (префикс — `[data] none_prefix`); без причины или с другим текстом — замечание.
- *Схема для редактора:* `yaml-schema`; *перевод* прежних файлов: `positional = ["dir", "with", "what"]` у поля и `yaml-migrate`. Порядок единиц папки — `_order.yaml`. Карточки блоков из единиц — `[blocks] data_kind`, `data_map` (поле карточки → ключ YAML), `data_sections` (вид блока → ключ).

YAML читает **PyYAML** (`pip install pyyaml`). Без него `yaml-check`, `yaml-fmt`, `unit` завершаются ошибкой «нужен PyYAML: pip install pyyaml» (код 1), карточки блоков из YAML и каталоги ID видов не строятся, а `check` пропускает проверку данных с предупреждением в stderr; `[data] require_yaml = true` — считать это замечанием. Журнал расхода может быть JSON — тогда PyYAML ему не нужен.

## Хуки <a id="hooks"></a>

| Где | Что вызывает |
|---|---|
| До правки файла (хук редактора, например Claude Code `PreToolUse` на Edit / Write) | `hook-pre` (или `pre <файл>`); код 2 — правка генерируемого файла запрещена, агенту называется источник |
| После правки (хук `PostToolUse`) | `hook-post` (или `post <файл>` и `next <файл>`) → в разговор агента: выжимка правил, следующие документы, замечания проверок |
| git `pre-commit` | `staged` |

Пример для Claude Code (`.claude/settings.json`):

```json
{
  "hooks": {
    "PreToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "python tools/doc hook-pre" }] }],
    "PostToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "python tools/doc hook-post" }] }]
  }
}
```

`hook-pre` / `hook-post` читают JSON хука из stdin (путь файла — `tool_input.file_path`, также `notebook_path` или `path`) и делают то же, что `pre` / `post`; `hook-post` возвращает текст в `hookSpecificOutput.additionalContext` (до 15 замечаний). Другие агенты зовут `pre` / `post` / `next` напрямую. git-хук `.git/hooks/pre-commit`: `#!/bin/sh` и `exec python tools/doc staged`.

## mdlinks.py — независимая проверка ссылок <a id="mdlinks"></a>

```bash
python tools/mdlinks.py [корень] [--entry README.md --entry AGENTS.md ...] [--no-orphans] [--no-anchors]
```

Проверяет все `*.md` под корнем (кроме `.git`, `node_modules`, `.venv`, `site`, `build`, `dist`):

- **битые относительные ссылки** `[текст](путь)` и `[текст](путь#якорь)` — файл или папка не существует;
- **битые якоря** — в целевом файле нет заголовка с таким GitHub-slug, явного `<a id="…">` / `id="…"` или `{#…}`;
- **«сироты»** — Markdown-файлы, на которые не ведёт ни одна ссылка из других файлов (кроме точек входа: по умолчанию `README.md`, `AGENTS.md`, `CLAUDE.md` в корне и `README.md` в любой папке).

Внешние ссылки (`http:`, `https:`, `mailto:`), ссылки-заглушки шаблонов вида `(<путь>)` и ссылки внутри блоков кода не проверяются. Код возврата 1 при замечаниях. Зависимостей нет (Python 3.8+). То же, с настройкой и стилем якорей MkDocs, — `tools/doc check --only links,anchors,orphans`.

## Что перенесено поведением, а что — только правилом

Поведение инструментов проекта-образца, перенесённое в `tools/doctool` обобщённо (по конфигу):

- `review-batch --pages <префикс>` — пачка документов по префиксу пути; `approve-batch` считает проверенным фактом также раздел «…», метод и код ответа HTTP, `#якорь` ([approvals.md](../rules/approvals.md#economy));
- `[data] guard_id_fields = ["via", "reqs", "decisions"]` — запись единицы (`yaml-fmt`, `yaml-migrate`, `write_unit`) не теряет ID из этих списков: ID, оставшийся в тексте строки, возвращается в поле, иначе запись отклоняется; `drop_ids=True` — намеренное удаление ([data.md](../rules/data.md#yaml-units));
- колонка «Тип» таблицы параметров (`parse_decl`, `value_ok`) и каталог значений из ключей словаря (`keys` в `[[data.catalogs]]`) — для каталога псевдонимов участников;
- `rnd-check`: мягкая проверка слоя 2 у R&D с «тип: архитектурное решение» в шапке ([rnd.md](../rules/rnd.md#layer2)).

Только правилом (в проекте-образце реализовано так-то, код не переносится — он завязан на структуру проекта):

- **покрытие сценариев подзадачами** (`doctool coverage`, входит в `check` предупреждением): сценарии требований из спек сравниваются с таблицей «Декомпозиция» файлов задач по основам слов и по перечням-диапазонам (`M0–M6`), блоки схем со статусом `todo` — с задачами компонента, блоки `back` — со строками бэклога; находок больше 40 — список в файл. Правило — [tasks.md](../rules/tasks.md); в вашем проекте — правило `lint` или плагин;
- **разбор `deck`-слайдов в `rnd-check`**: проект-образец прогоняет блоки ```` ```deck ```` тем же разбором, что и сборка сайта; в methodology сайта нет;
- **карточка документа без эндпоинтов**: если у страницы нет своих эндпоинтов в данных, в карточку идёт текст документа, а не пустой список (в `card` — способ `sections`, плагином `@card_kind` при необходимости).
