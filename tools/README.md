# Инструменты: контракт команд

← [README](../README.md) · [AGENTS.md](../AGENTS.md) · [путь изменения](../rules/agent-workflow.md)

Правила сами по себе дороги: агент тратит контекст на чтение всех методологий и всё равно пропускает нужное. Поэтому правило подаётся **в момент правки** инструментом, а проверки — автоматически. Здесь — набор команд, которые стоит реализовать в проекте (одна утилита `doc <команда>`), и их контракт. Реализация зависит от раскладки репозитория, поэтому её здесь нет; независимая от проекта часть — [mdlinks.py](#mdlinks).

## Принципы

- **Без копий правил.** Выжимки строятся из таблиц `rules/` при каждом вызове (колонки «Где», «Обязательные разделы», «Правила», «Синхронизировать», «Методология» в [doc-types.md](../rules/doc-types.md)). Изменили таблицу — изменился ответ инструмента.
- **Быстро.** `check` — секунды, без сборки сайта, чтобы его можно было звать после каждой правки.
- **Для любого агента.** Команды — обычный CLI; хуки конкретного редактора — тонкая обёртка над `pre` / `post`.
- **Инструменты соответствуют правилам** — это тоже проверка (`check` включает её): методологии из таблицы существуют, пути в сценариях и `AGENTS.md` есть, `route` узнаёт основной путь каждого типа, у узлов графа есть файлы.

## Команды

| Команда | Вход | Выход | Код возврата |
|---|---|---|---|
| `route <файл>` | путь | тип документа, вкладка, обязательные разделы, правила, источник факта, что синхронизировать, ссылка на методологию — из строки [doc-types.md](../rules/doc-types.md), найденной по шаблону «Где» | 0 |
| `pre <файл>` | путь | пусто, если файл не генерируется; иначе — «генерируется <чем>, правь <источник>» в stderr | 2 — файл генерируется (хук запрещает правку) |
| `post <файл>` | путь | выжимка `route` + замечания `check` | 0 |
| `generated <файл>` | путь | «генерируется: <чем>; править: <источник>» или пусто | 0 |
| `next <файл>` | путь | узел графа ([doc-graph.md](../rules/doc-graph.md)) и документы на концах стрелок: путь, что проверить, методология каждого | 0 |
| `check` | — | все строгие проверки: ссылки и якоря, трассировка требование ↔ задача, коды интерфейсов и хранилищ с обеих сторон, примеры = поля моделей, обязательные разделы, соответствие инструментов правилам | 1 — есть замечания |
| `lint [компонент]` | — | нестрогие проверки методологий по компонентам (экраны без эндпоинтов, изменяющие эндпоинты без кодов ошибок, подзадачи без «готово, когда», процессы без веток ошибок, встроенные компоненты вне зоны хоста, нет «Обновление и откат») | 0 — не блокирует коммит |
| `staged` | индекс git | `check` + запрет коммита изменённых генерируемых файлов | 1 — коммит нельзя |
| `move <старый> <новый>` | два пути | перенос файла (`git mv`) и замена всех относительных ссылок и упоминаний пути во всех документах, сценариях и файлах данных; список изменённых файлов | 0 |
| `diagram <файл>` | путь | HTML-страница со всеми блоками ` ```mermaid ` файла, отрисованными (mermaid из CDN); выводит её URI | 0 |
| `rnd <slug> <тема>` | slug, тема | файл R&D по [шаблону](../templates/rnd.md), проходящий проверку структуры; отказ, если файл есть | 0 |
| `blocks` | — | заполненность карточек блоков: сколько полных, у каких чего нет ([блоки](../rules/blocks.md)) | 0 |
| `review-pack <страница> <буква>` | страница, роль | **один файл** для проверяющего: страница, вопрос роли, чек-лист методологии типа, требования страницы, открытые вопросы, прежние замечания, lint; путь и размер в токенах | 0 |
| `review-queue [буква]` | роль | пары «документ × роль» со статусом ⏳ | 0 |
| `approve <страница> <буква> ok\|no "<комментарий>" [--human]` | решение | строка реестра подтверждений: кто, 🤖 / 👤, дата, ✅ / ❌, версия текста (хеш), комментарий | 0 |
| `finding <компонент> <ID[,ID]> ok\|wait\|owner "<что сделано>"` | замечания | статус ✅ / ⏳ / 📌 в файле замечаний компонента ([ревью](../rules/review.md#findings)) | 0 |

Синхронизация реестра подтверждений (при сборке или в `check`): строки ⏳ для обязательных пар «документ × роль» по таблице [подтверждений](../rules/approvals.md); сброс решения в ⏳, если хеш текста документа изменился; удаление строк удалённых документов.

## Хуки <a id="hooks"></a>

| Где | Что вызывает |
|---|---|
| До правки файла (хук редактора, например Claude Code `PreToolUse` на Edit / Write) | `pre <файл>`; код 2 — правка генерируемого файла запрещена, агенту называется источник |
| После правки (хук `PostToolUse`) | `post <файл>` и `next <файл>` → в разговор агента: выжимка правил, следующие документы, замечания проверок |
| git `pre-commit` | `staged` |

Пример для Claude Code (`.claude/settings.json`), если утилита — `tools/doc`:

```json
{
  "hooks": {
    "PreToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "tools/doc hook-pre" }] }],
    "PostToolUse": [{ "matcher": "Edit|Write", "hooks": [{ "type": "command", "command": "tools/doc hook-post" }] }]
  }
}
```

`hook-pre` / `hook-post` читают JSON хука из stdin (путь файла — `tool_input.file_path`) и делают то же, что `pre` / `post`; `hook-post` возвращает текст в `hookSpecificOutput.additionalContext`.

## mdlinks.py — независимая проверка ссылок <a id="mdlinks"></a>

```bash
python tools/mdlinks.py [корень] [--entry README.md --entry AGENTS.md ...] [--no-orphans] [--no-anchors]
```

Проверяет все `*.md` под корнем (кроме `.git`, `node_modules`, `.venv`, `site`, `build`, `dist`):

- **битые относительные ссылки** `[текст](путь)` и `[текст](путь#якорь)` — файл или папка не существует;
- **битые якоря** — в целевом файле нет заголовка с таким GitHub-slug, явного `<a id="…">` / `id="…"` или `{#…}`;
- **«сироты»** — Markdown-файлы, на которые не ведёт ни одна ссылка из других файлов (кроме точек входа: по умолчанию `README.md`, `AGENTS.md`, `CLAUDE.md` в корне и `README.md` в любой папке).

Внешние ссылки (`http:`, `https:`, `mailto:`), ссылки-заглушки шаблонов вида `(<путь>)` и ссылки внутри блоков кода не проверяются. Код возврата 1 при замечаниях. Зависимостей нет (Python 3.8+).
